# ✅ **5. rag.py — RAG logic**

**app/rag.py**

```python
from langchain_community.document_loaders import DirectoryLoader, PyPDFLoader
from langchain.text_splitter import RecursiveCharacterTextSplitter
from sentence_transformers import SentenceTransformer
import chromadb
from langchain_community.vectorstores import Chroma
from langchain_community.llms import Ollama
from langchain.chains import RetrievalQA

# 1. Load PDFs
loader = DirectoryLoader("./data", glob="**/*.pdf", loader_cls=PyPDFLoader)
documents = loader.load()

# 2. Chunking
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=50)
docs = splitter.split_documents(documents)

# 3. Embeddings
embedder = SentenceTransformer("all-MiniLM-L6-v2")

# 4. Vector DB
vectordb = Chroma(
    persist_directory="./chroma_store",
    embedding_function=lambda texts: embedder.encode(texts).tolist()
)

vectordb.add_documents(docs)

# 5. LLM connection (inside Docker network)
llm = Ollama(model="llama3", base_url="http://ollama:11434")

# 6. RAG chain
qa = RetrievalQA.from_chain_type(
    llm=llm,
    chain_type="stuff",
    retriever=vectordb.as_retriever()
)

def ask_question(q):
    return qa.run(q)
```

# ✅ **6. FastAPI server**

**app/api.py**

```python
from fastapi import FastAPI
from pydantic import BaseModel
from rag import ask_question

app = FastAPI()

class Query(BaseModel):
    question: str

@app.post("/ask")
def ask(q: Query):
    answer = ask_question(q.question)
    return {"answer": answer}
```

# 🚀 **How Your Basic RAG System Works (Easy Explanation)**

Your RAG system has **3 major parts**:

1.  **Document Processing**
2.  **Retrieval (finding the right information)**
3.  **Generation (LLM answers using retrieved info)**

Everything happens automatically when you ask a question.

---

# ✅ **STEP 1 — Load Your Documents (PDFs → Text)**

When you run your script:

```python
loader = DirectoryLoader("./data", glob="**/*.pdf", loader_cls=PyPDFLoader)
documents = loader.load()
```

The system:

- Enters the `data/` folder
- Opens every **PDF**
- Extracts all text inside them
- Converts that text into a format the system can work with

📌 **Goal:** Get raw text to feed into the RAG pipeline.

---

# ✅ **STEP 2 — Split Documents Into Chunks (Chunking)**

LLMs cannot process long documents at once.  
So you break your PDFs into **small pieces**:

```python
splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50
)
docs = splitter.split_documents(documents)
```

Now you have chunks like:

- Chunk 1 → Page 1 (first 500 characters)
- Chunk 2 → next 500 characters (with 50 overlapping)
- Chunk 3 → next 500 characters
- …

📌 **Why?**  
Because retrieval works better on smaller, meaningful pieces.

---

# ✅ **STEP 3 — Convert Chunks to Embeddings (Vectors)**

This is the “brain” behind RAG.

```python
embedder = SentenceTransformer("all-MiniLM-L6-v2")
```

This model turns each chunk into a **vector** (a list of numbers).

Example vector:

    [0.12, -0.55, 0.91, 0.02, ...]

📌 **Why?**  
Because similar text has **similar vectors** — this makes searching super fast and accurate.

---

# ✅ **STEP 4 — Store Embeddings in a Vector Database**

You store all those vectors in **ChromaDB**:

```python
vectordb = Chroma.from_documents(...)
```

Think of ChromaDB as:

🧠 A **searchable memory** of your documents  
You ask a question → it finds the closest matching text chunks

It works like:  
“Which chunks have similar meaning to this question?”

---

# ✅ **STEP 5 — Ask a Question (Query → Vector)**

When you type a question:

    Ask: what does section 3 say?

What happens internally:

1.  Your question is also turned into an embedding vector.
2.  ChromaDB compares your vector to all stored vectors.
3.  It returns the **top most relevant chunks** (example: 3‑5 pieces of text).

Example returned chunks:

- A paragraph from page 2
- A section from page 4
- A summary from page 1

These chunks are then passed to the LLM.

---

# ✅ **STEP 6 — LLM Writes the Answer Using Retrieved Text**

Using Ollama:

```python
llm = Ollama(model="llama3")
```

The RAG chain:

```python
qa = RetrievalQA(...)
```

What happens:

- The retrieved document chunks are placed in the **prompt**
- The LLM is told:
  “Use ONLY this content to answer the question.”

Example prompt (hidden from you):

    Context:
    [Chunk 1 text...]
    [Chunk 2 text...]

    Question:
    What does section 3 say?

    Answer:

📌 **This is the magic!**  
The LLM answers based on **facts from your documents**, not from its imagination.

---

# ✅ **STEP 7 — Final Answer to the User**

The LLM generates:

- Summary
- Explanation
- Answer with context

And prints it in your terminal.

# 🎯 **In Simple Words: What Happens Behind the Scenes**

Think of it as:

### **1. Your documents are chopped up into small pieces**

### **2. Each piece is turned into a mathematical fingerprint (vector)**

### **3. When you ask something, your question is also fingerprinted**

### **4. The system finds the closest matching pieces**

### **5. LLM reads only those pieces and answers based on them**

That's it — simple, powerful, free.
